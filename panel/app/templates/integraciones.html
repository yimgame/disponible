Integraciones (n8n / agente de IA)

El disponible avisa a n8n de cada evento (webhook) y n8n puede consultar y cargar datos con la API. Con las dos cosas se engancha un agente de IA.

Cada evento llega por POST con este formato:

{
  "evento": "movimiento" | "alerta_bloqueo" | "uso" | "uso_anulado" | "prueba",
  "enviado": "2026-11-19T10:15:00-03:00",
  "datos": { ... }   // el movimiento (con "alertas"), el uso, etc.
}

Headers: X-Disponible-Evento y, si hay secreto, X-Disponible-Firma: sha256=<HMAC del cuerpo> para validar que viene del disponible. Ejemplo de uso: un flujo de n8n con un Webhook → AI Agent que, ante una alerta_bloqueo, le escribe al transporte por WhatsApp.

2 · API para agentes (n8n → Disponible)

{% if api %}

✔ Activa. Autenticación: header Authorization: Bearer <AGENTE_API_KEY> (la llave está en el .env del servidor).

{% else %}

Desactivada. Definí AGENTE_API_KEY en el .env del servidor (una clave larga al azar) y reiniciá el panel.

{% endif %}

Base: {{ base }}/api/v1. Cada endpoint sirve como HTTP Request Tool de un AI Agent en n8n.

Método y rutaPara qué
GET /api/v1/estado?fecha=AAAA-MM-DD&transporte_id=Disponible del día: unidades (disponibles / usadas, ETA, chofer, bloqueos), totales y cuota por transporte.
GET /api/v1/transportesTransportes (id, nombre, nº de proveedor, cuota, celular).
GET /api/v1/unidad/{patente}Maestro de la unidad, GCG, bloqueos y alertas.
GET /api/v1/chofer/{dni}GCG del chofer, bloqueos y alertas.
POST /api/v1/movimientosCargar o sacar una unidad: {transporte_id, patente, accion: "agrega"|"quita", tipo: "refri"|"seco", pallets, eta, chofer_dni, comentario}.
POST /api/v1/usosUsar una unidad: {patente, destino, viaje, planta, detalle, fecha}.
GET /api/v1/usos?desde=&hasta=&transporte_id=Usos de un rango (dónde se usó cada unidad).

Ejemplo: curl -H "Authorization: Bearer $AGENTE_API_KEY" {{ base }}/api/v1/estado
